# Symptom → Cause → Fix Lookup

| Symptom | Likely Cause | Fix |
|---|---|---|
| `refusing to auto-apply N pending schema migrations to a remote-backed database (vX -> vY): migrating clones independently forks the schema` | A newer bd version opened the DB (e.g., watcher app, agent) but cannot safely apply migrations because a Dolt remote is configured — doing so would fork the schema across clones | Run `bd migrate schema --force && bd migrate --force` on the **primary host** (in `bd v1.3.x+`, `bd migrate --force` alone only updates metadata without applying SQL table migrations), then `bd vc commit -m "chore(bd): commit config working set"`, `bd recompute-blocked --json`, `bd hooks install --force`, and `bd dolt push`. Clones must `bd dolt pull` before opening with the new version. |
| `Error: legacy Dolt server workspace from bd 0.60.0 detected; explicit migration is required` | Cross-era guard in `bd v1.3+`: `.beads/metadata.json` has `dolt_mode: server` with a pre-v1 `.beads/.local_version` witness (`v0.55.4`–`v0.62.0`) | Do NOT run `scripts/repair.sh` directly. Inspect raw Dolt row count (`dolt --data-dir .beads/dolt sql -q "use <db>; select count(*) from issues;"`) vs `.beads/issues.jsonl`. If legacy DB is empty or behind git JSONL: snapshot `.beads/`, clear `.beads/dolt`, `.beads/backup`, `.beads/.local_version`, `.beads/dolt-server.*`, re-init with `bd init --server --reinit-local --prefix <p> --database <db> --non-interactive --skip-agents`, then `bd import .beads/issues.jsonl`, `bd recompute-blocked --json`, `bd hooks install --force`. See **Case J** in `references/recovery-playbook.md`. |
| `bd doctor`: `Tracked Runtime Files: 1 tracked file(s) include sensitive data (credential key)` (`.beads/.beads-credential-key`) | Legacy `bd` versions tracked `.beads/.beads-credential-key` before it was added to `.beads/.gitignore` | Run `git rm --cached .beads/.beads-credential-key` (ensure `.beads-credential-key` is in `.beads/.gitignore`) and commit |
| `bd doctor`: `Git Hooks: Installed bd hooks are outdated` (`pre-commit@0.60.0` etc.) | `.git/hooks/*` still contain wrappers installed by an older `bd` release | Run `bd hooks install --force` |
| `Error: search count issues: Error 1105 (HY000): table "i" does not have column "storage_class"` on `bd list` | `.beads/.local_version` was already stamped with the new CLI version (`1.3.1+`), so `bd list` skips the migration prompt and queries un-migrated schema (`v53` vs `v66`) directly | Run `bd migrate schema --force && bd migrate --force`, then `bd vc commit -m "chore(bd): commit config working set"` and `bd sync` (or `bd dolt push`) |
| `column "content_hash" could not be found in any table in scope` in dolt-server.log | A client is querying columns added in a newer schema version that has not been migrated yet (symptom of the above migration block) | Apply pending migrations: `bd migrate schema --force && bd migrate --force && bd dolt push`, then restart any reader/watcher using the new bd version |
| `bd export --all` (or `bd export`) fails with `column "X" could not be found in any table in scope` during a schema skew | `bd export` runs the failing query directly instead of hitting the gate check — it is NOT a safe pre-migration backup during active skew | Take a raw filesystem copy of `.beads/dolt` instead (`cp -R .beads/dolt /tmp/bd-raw-snapshot-...`) before migrating |
| `bd migrate --force` fails: `pending schema migrations alter pre-existing dirty tables: issues; run 'bd dolt commit' ...` | Uncommitted Dolt working-set changes block migration | `bd dolt commit` (the suggested fix) hits the *same* gate and fails identically — chicken-and-egg. Commit via the raw `dolt` CLI instead: `dolt --data-dir .beads/dolt sql -q "use <db>; CALL DOLT_COMMIT('-a','-m','...')"` (after confirming `dolt_diff_summary(...)` shows `schema_change = 0`), then retry `bd migrate --force`. See **Schema Version Skew** in SKILL.md. |
| `Error: --force cannot be combined with --dry-run` on `bd migrate` | `--force` opens the store and applies migrations immediately, which is incompatible with a dry-run preview | Drop `--dry-run`, or preview with `bd migrate --inspect` instead (read-only) |
| `bd doctor`: `schema version mismatch: database is at vX, binary knows up to vY (N migrations ahead)` | **Inverse skew** — your bd binary is OLDER than a DB another agent/machine already migrated forward. Reads warn, writes fail. NOT corruption. | **Upgrade the client binary** using `scripts/restore-bd.sh` (defaults to `@latest` with CGO; pass `./scripts/restore-bd.sh --main` if DB was migrated past the latest release tag — do NOT set `CGO_ENABLED=0`). See **Schema Version Skew — Client BEHIND the Database** and `references/cgo-and-schema-drift.md`. |
| `Error: failed to open database: database "<name>" not found on Dolt server at 127.0.0.1:<port>` | Fresh clone (or new machine) where `.beads/metadata.json` specifies `dolt_mode: "server"`, `.beads/dolt/<name>` doesn't exist yet (runtime state is gitignored), OR `bd bootstrap` imported into `.beads/embeddeddolt/<name>` instead of `.beads/dolt/<name>` | Run `scripts/repair.sh` (or `bd bootstrap --yes` with `>=180s` timeout, then if `.beads/embeddeddolt/<name>` was created, stop scoped server, move it to `.beads/dolt/<name>`, clear `.beads/dolt-server*`, `bd dolt start`, `bd doctor --fix --yes`, `bd vc commit`). See `references/recovery-playbook.md` **Case I**. |
| `Error: Bootstrap failed: clone from remote ... 403 AccessDenied` followed by `bd init refuses: remote 'origin' already has Dolt history` (`git: 'remote-gs' is not a git command`) | Fresh clone with `sync.remote` pointing to an inaccessible GCS bucket (wrong ADC account or offline) while `.beads/issues.jsonl` is tracked in git | Either switch ADC credentials and re-run `bd bootstrap --yes`, or recover locally from `.beads/issues.jsonl`: temporarily strip `sync:` from `.beads/config.yaml`, run `bd init --server --reinit-local ...`, restore `config.yaml`, run `bd import .beads/issues.jsonl && bd recompute-blocked --json`, restore Dolt `origin` remote, and undo implicit git auto-commits (do not push unrelated Dolt ancestry to GCS). See **Case I (Sub-case I.2)** in `references/recovery-playbook.md`. |
| `bd dolt show` prints `Remotes: (none)` even though `sync.remote` / Dolt `origin` is configured | In server mode, `bd dolt show` may omit remotes configured inside the Dolt database | Verify remotes with `bd dolt remote list` rather than relying on `bd dolt show`. |
| `bd doctor` shows `Federation remotesapi: remotesapi port 8080 not accessible` alongside `Database: Unable to open database` | Cascading false-positive error when the configured `<dolt_database>` does not exist yet on the auto-started `dolt sql-server` | Fix the missing server-mode database first (`scripts/repair.sh` / **Case I**); the Federation error disappears once `<dolt_database>` opens cleanly. |
| `bd doctor` after `bd doctor --fix --yes` warns `Dolt Status: 1 uncommitted change(s) [metadata: modified]` and `Dolt Locks: Uncommitted changes detected` | `bd doctor --fix` backfilled `project_id` / `repo_id` in the `metadata` table without committing the Dolt working set | Run `bd vc commit -m "chore(bd): commit doctor metadata fixes"` |
| `bd doctor` warns `Git Hooks: Installed bd hooks are outdated` after upgrading `bd` | `.git/hooks/*` scripts still carry the previous CLI version stamp | Run `bd hooks install --force` (only after `bd dolt start` is already running if in server mode) |
| `bd doctor`: `Skipped: requires CGO` across maintenance and patrol checks | Binary was compiled in pure-Go mode (`CGO_ENABLED=0`), disabling embedded SQLite and Dolt diagnostic test suites | Rebuild with full CGO + ICU bindings by running `scripts/restore-bd.sh`; see `references/cgo-and-schema-drift.md` |
| `failed to record event: record event in events: Error 1105 (HY000): Field 'id' doesn't have a default value` on any `bd update`/`bd close` | The old binary is writing to a newer `events`-table schema it doesn't understand (inverse schema skew) | Upgrade the client binary using `scripts/restore-bd.sh` |
| `go install` of bd fails: `fatal error: 'unicode/regex.h' file not found` | Recent bd pulls `dolthub/go-icu-regex` (CGO) which needs native ICU C++ development headers | Run `scripts/restore-bd.sh` for automated OS/ICU setup, or see `references/cgo-and-schema-drift.md` for manual macOS/Linux packages |
| "I upgraded bd but `bd --version` still shows the old version" | `go install` wrote to `~/go/bin` but PATH `bd` is a stale copy elsewhere (e.g. `~/.local/bin/bd`) | `scripts/restore-bd.sh` automatically synchronizes shadowed PATH binaries, or manually run `cp -f ~/go/bin/bd "$(which bd)" && hash -r` |
| `daemon-error` file contains "DATABASE MISMATCH DETECTED" | Repo ID in DB doesn't match current git remote (bd upgrade, URL change, or copied `.beads/`) | `bd migrate --update-repo-id --yes`; if mismatch persists after reinit, it may already be resolved — check `bd list` |
| `bd doctor` shows `Repo Fingerprint: Database belongs to different repository` (no `daemon-error` file) | Repo fingerprint in DB was calculated before a git remote origin was added | `bd migrate --update-repo-id --yes` |
| `bd doctor` shows `Dolt Remote vs Git Origin: 1 Dolt remote(s) match the git origin URL: origin` | `bd init` auto-populated `sync.remote` and Dolt's `origin` remote with the git SSH URL (`git+ssh://...`) | **Do NOT blindly set `dolt.local-only: true`** if remote viewers (`beads-run` / GCS federation) rely on Dolt sync. Check `git log -p -- .beads/config.yaml` and sibling projects (`grep -h -A1 "^sync:" ~/projects/*/.beads/config.yaml`) for a GCS bucket (`gs://<bucket>/<project-id>`). If federated via GCS: set `sync.remote: "gs://<bucket>/<project-id>"` in `.beads/config.yaml`, run `bd dolt remote remove origin && bd dolt remote add origin gs://<bucket>/<project-id>`, then `bd dolt push --no-adopt && bd sync`. Only use `bd config set dolt.local-only true` if confirmed strictly local-only. |
| `bd dolt status` shows `Remote sync: disabled (dolt.local-only=true)` and remote viewers (`beads-run`) are missing or stale | An agent or `bd init` added `dolt: local-only: true` to `.beads/config.yaml` to silence `Dolt Remote vs Git Origin`, disabling all remote sync | Remove `dolt: local-only: true` from `.beads/config.yaml`, restore `sync.remote: "gs://<bucket>/<project-id>"` and Dolt `origin` (`bd dolt remote remove origin && bd dolt remote add origin gs://<bucket>/<project-id>`), and run `bd dolt push --no-adopt && bd sync` |
| Any bd command fails with "hyphens are not allowed in embedded mode" | `dolt_database` contains hyphens; embedded mode forbids them | Switch to server mode: `bd init --server --reinit-local --database <name> --non-interactive` |
| `bd dolt show` reports `Mode: embedded` but `.beads/dolt/` contains data | bd was upgraded or re-initialized without `--server`; engine mode is wrong | `bd init --server --reinit-local --database <name> --server-port <port> --non-interactive --skip-hooks --skip-agents`; find `<name>` with `ls .beads/dolt/` and `<port>` in `.beads/dolt/config.yaml` |
| `bd close`/`bd update` prints success but reverts on next command | Corrupt `.beads/backup/` → export fails → next command re-imports stale JSONL and reverts | `scripts/repair-corrupt-backup.sh` |
| `auto-backup failed ... table file not found` in dolt-server.log | Backup manifest references deleted table files | Move backup aside; let bd recreate it |
| `bd show X` disagrees with `.beads/issues.jsonl` | Export to JSONL is failing silently | `bd export -o .beads/issues.jsonl` after confirming Dolt state |
| Same corruption returns after a fresh `git clone` | `.beads/backup/` was committed to git | `git rm --cached -r .beads/backup/` and commit |
| `nothing to commit` warnings from Dolt | Benign — no pending Dolt changes | Ignore |
| "auto-importing into empty database" on every command | Normal bd behavior with `no-db = true` in `.beads/config.yaml` | Not a problem by itself |
| Only one write "sticks" per session | The import-revert loop | Batch writes, verify with `bd show`, then single `bd export` |
| `bd dolt status` shows server not running | Server crashed or never started | `bd dolt start` |
| Stale `.beads/dolt-server.pid`/`.port` cause connection errors | Runtime files tracked/leftover | Untrack them; restart server |
| `server started (PID N) but not accepting connections … timeout` + log repeats `database "dolt" is locked by another dolt process` | Another `dolt sql-server` holds the single exclusive write lock (another project, or a bind-mounted `.beads/` shared by host + container) | `scripts/find-dolt-server.sh` to isolate this repo's server by CWD; `bd dolt stop` (scoped); clear stale runtime files; `bd dolt start`. See recovery-playbook Case F |

## Distinguishing real corruption from normal noise

These are **normal** and not problems on their own:
- `auto-importing N bytes ... into empty database`
- `auto-imported N issues`
- Dolt `nothing to commit` warnings

These indicate **real** problems:
- `table file not found`
- `auto-backup failed: sync to backup`
- `bd show` vs JSONL mismatch
- writes that revert
- `refusing to auto-apply N pending schema migrations to a remote-backed database`
- `column "X" could not be found in any table in scope` (schema version skew)
- `schema version mismatch: database is at vX, binary knows up to vY` (inverse skew — client behind DB)
- `Skipped: requires CGO` across core tests in `bd doctor` (binary compiled without CGO/ICU support)
- `Field 'id' doesn't have a default value` on writes (inverse skew — old binary writing newer `events` schema)
- `pending schema migrations alter pre-existing dirty tables` on `bd migrate --force` (dirty working set blocks migration — needs the raw-`dolt`-CLI commit workaround, not the suggested `bd dolt commit`)
